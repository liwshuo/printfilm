# 4 项目工作流交互设计调研报告

> 调研人：李硕（胖哥）｜时间：2026-09-23  
> 目的：为 printfilm-next 的「流式化 + AI 主动填充」改造，从 4 个 GitHub 参考项目里抽取可复用的交互 pattern。  
> 调研方法：拉取各仓库 README（含 zh-CN）、skill 目录列表与技能链，反推用户旅程；未做代码级审计。

---

## 摘要

- **共性 pattern（4 个项目都在做的事）**：都把「从零到成片」显式切成 **有序阶段 + 每阶段一份产物文件**——只是载体从「多个 CLI 命令」到「多个 Skill」到「左侧进度栏页面」不等；都强制「上一阶段产物 = 下一阶段输入」，杜绝手工搬运；都有明确的「AI 生成大部分内容 / 用户只给 seed + 确认」的分工，用户手填的字段极少（题材、集数、原文粘贴、Key）。
- **差异 pattern**：
  1. **驱动形态**：`0xsline/short-drama` 与 `zenstory-ai/drama-skills` 走 **CLI-Command / Skill 命令流**（`/start → /plan → /episode`），状态在 `.drama-state.json` 或多份 Markdown 里；`huobao-drama` 与 `CineGen` 走 **图形工作台 + 左侧阶段进度条**（Phase 01/02/03/04），页面切换 = 阶段推进。
  2. **AI 主动填充深度**：`short-drama` 靠「题材 → 自动带出钩子占比 / 反派体系 / 节奏曲线 / 爽感矩阵」这种**基于知识库的规则型 pre-fill**；`CineGen` 与 `zenstory` 靠「上一层文件里的锁面/连续性锁字符串**原样注入**下一层提示词」的**字段级引用型 pre-fill**；`huobao` 走「粘贴小说 → 一键 AI 改写 → 一键提取角色/场景/道具」的**批量抽取型 pre-fill**。
  3. **确认闸门**：`zenstory` 是唯一显式把「预览 → 用户明确确认 → 才调用外部付费接口」写成核心 Skill（`short-drama-produce`）的项目；`huobao` 用「批量生成前弹窗确认镜头数 / 时长 / 模型 / 分辨率」实现同一意图；另外两个偏 Skill / 命令的项目确认闸门较隐式。
  4. **可视化程度**：`huobao` / `CineGen` 有网格化分镜表 + 时间轴预览；`short-drama` 输出 ASCII 情绪波形与钩子占比表；`zenstory` 提供 `dashboard` 本地 Web 面板，但仍以文件为事实源。

## 项目 1：0xsline/short-drama

### 定位与产品形态
- **AI 短剧剧本创作 Skill 包**（Claude Code / Codex / Gemini CLI），零依赖纯 Markdown 规则文件，仓库自身没有 GUI，工作台就是 AI 编程助手 + 工作目录里的文件。
- 覆盖「选题 → 骨架 → 角色 → 分集目录 → 分集剧本 → 质量审查 → 合规 → 导出」全流程，13 种题材模板 + 四层反派体系 + 五种钩子 + 节奏曲线 + 付费卡点。

### 用户完整旅程（Zero → 第一集完整脚本）

| 步 | 命令 | 输入 | 输出 |
|---|---|---|---|
| 1 | `/start` | **表单式选项**：题材（13 选 1-2）/ 受众 / 调性 / 结局 / 集数 / 语言 / 模式（国内 / 海外） | `.drama-state.json`（状态文件，后续命令自动读取） |
| 2 | `/plan` | 自动读 state | `creative-plan.md`（8 板块：人物名单 / 背景 / 主副线 / 三幕 / 节奏曲线 / 付费卡点 / 爽感矩阵 / 结局） |
| 3 | `/characters` | 自动读 plan | `characters.md`（档案 + Mermaid 关系图 + 弧光 + 感情线 + 四层反派） |
| 4 | `/outline` | 自动读 characters | `episode-directory.md`（分集目录，每集：标题 / 梗概 / 钩子类型 / 🔥 重点 / 💰 付费标记） |
| 5 | `/episode 1` | 自动读 outline | `episodes/ep001.md`（含元信息条 + 场景 + 结尾钩子 + 下集预告） |
| 6 | `/review 1` | 读 ep001 | `reviews/ep001-review.md`（5 维度评分表 + 亮点 + 问题分级 + ASCII 情绪波形） |

**关键点**：从 `/start` 到「第一集脚本」是**固定 5 步链**，用户只在第 1 步填过一次表单，中间步骤都是「一句命令 → AI 生成完整产物」。

### AI 参与度 vs 用户手填
- **用户手填**：只在 `/start` 里勾选 7 个字段（题材 / 受众 / 调性 / 结局 / 集数 / 语言 / 模式），全部是**下拉 / 单选**，没有自由文本必填。
- **AI 生成**：故事骨架 8 板块、角色档案、四层反派、分集目录、每集剧本、5 维度审查评分——全部由 AI 基于 state + references 生成。
- **AI 提议 → 用户确认**：**没有显式「3 选 1」**，而是「AI 一次性给完整产物 → 用户在 Markdown 里手动改」；`/review` 会给分级问题清单（⛔ 阻断 / ⚠️ 建议 / ℹ️ 微调）让用户回头修。

### Wizard / step-by-step 设计
- **强线性 CTA**：每个命令都写明「**前置条件**」（`/plan` 需先执行 `/start`；`/characters` 需先 `/plan`），阻塞式往前推。
- **进度可视化**：靠 `.drama-state.json` 里的 `currentStep` + `completedEpisodes[]` 字段，但**没有 GUI 进度条**，是命令行提示。
- README 里的「快速上手」段就是**一段可粘贴的 9 行命令序列**，等于把 Wizard 写成了脚本。

### 智能填充 & 建议模式
- **规则型 pre-fill 是本项目最大亮点**：
  - `/plan` 会自动按题材从 `references/genre-guide.md`、`rhythm-curve.md`、`paywall-design.md`、`satisfaction-matrix.md` 加载知识库，输出**已填好数值的**「节奏曲线（起势 15% / 攀升 30% / 风暴 35% / 决战 20%）」「付费卡点 10-15%」「爽感矩阵 8 类要素占比」。
  - `/outline` 生成时钩子类型占比按参考值分配（情绪钩 30-40% / 悬念钩 20-30% / 危机钩 10-20%…）。
  - `/characters` 自动生成四层反派体系（小 / 中 / 大 / 隐藏），并把每层活跃时段填成 `前 1/4 → 前 2/3 → 中后期 → 后 1/3`。
- **参考文档按需加载**：不是把 8 份 references 全塞给模型，而是**每个命令只加载它相关的**（`/episode` 第 1-3 集时才加 `opening-rules.md`），这是节省上下文的 pattern。
- **一键改进**：`/review` 给出问题清单，`/episode next` 检测进度自动写下一集，`/overseas` 一键切海外格式（△ → WIDE SHOT，配乐英译，角色名转拼音）。

### 状态机与数据流
- **状态机**：`.drama-state.json` 里 `currentStep: start | plan | characters | outline | episodes | review | export`；`completedEpisodes: [1,2]` 追踪进度。
- **数据流**：完全自动流转，每个命令读上一个产物文件 + state → 写下一个产物文件；用户不需要 copy/paste。
- **审查产物独立**：`reviews/` 与 `episodes/` 并行存在，方便审查报告不污染剧本主稿。

### 对 printfilm-next 的可借鉴点
1. **把「题材 / 内容类型 / 视觉风格」的每个组合预置一份「参考值表」**（钩子占比、节奏曲线、付费卡点、爽感矩阵），当用户选定 `contentType=short_drama + visualStyle=xxx` 时，故事圣经 / 系列设定的对应字段**自动 pre-fill 数值草案**，用户只需微调 → 直接解决"字段多、不知填什么"的痛点。
2. **在项目根写一份 `.printfilm-state.json`（或复用 SQLite 里的 project 表）**，记录 `currentStep`、`completedEpisodes[]`，story workspace 顶部展示"当前阶段：分集大纲 → 下一步：生成 EP1 场次"的固定 CTA。
3. **按需加载参考文档 pattern**：Prompt Center 编译系统提示词时，按「当前 contentType + 当前 step」按需注入 references，不要一股脑塞满上下文。
4. **`/review` 五维度评分 + ASCII 波形**可以搬成"分集卡片右上角小徽章 + hover 展开评分表 + 分级问题清单"。
5. **命令序列文档化**：README 的 9 行命令序列可以搬成 printfilm-next 首页的「开始新项目」引导——一屏内展示「第 1 步 / 第 2 步…第 6 步」，每步一个卡片 + 一个 CTA 按钮。

## 项目 2：chatfire-AI/huobao-drama

### 定位与产品形态
- **端到端图形工作台**（Nuxt 3 + Hono + SQLite + Electron 桌面版），从「粘贴小说」到「导出成片 MP4」一站式，内置 4 个 Mastra Agent（script_rewriter / extractor / storyboard_breaker / prompt_generator）+ 多厂商图片视频 adapter。
- README 明确写了「**左侧进度栏始终标示当前所处阶段，跟着走即可**」——这就是他们对流式化的核心答案。

### 用户完整旅程（Zero → 第一集成片 MP4）

| 步 | 页面 | 输入 | 输出 |
|---|---|---|---|
| 1 | **新建项目** | 剧名、画面比例（横 16:9 / 竖 9:16，**不可改**）、画面风格（3D / 真实感等，**全局注入生图提示词**） | 项目卡片 |
| 2 | **设置 → 火宝快捷配置** | 粘贴一个 API Key | 一键写入文本 / 图片 / 视频 3 条推荐配置，横幅消失 |
| 3 | **剧本阶段** | 粘贴**原始小说文本** | AI 改写为**按集拆分、标注场景与角色**的拍摄剧本；可换模型、调语气；"保存并进入制作" |
| 4 | **资产制作** | 对剧本按钮"提取" | 自动获得**角色 / 场景 / 道具**清单；逐个点"生成形象"产参考图（也可批量） |
| 5 | **视频制作 - 拆分分镜** | 剧本 + 资产 | AI 按镜头节奏切分 + **自动生成视频提示词**；`@角色名` 自动映射参考图 |
| 6 | **视频制作 - 批量生成** | 顶栏选视频模型（Seedance / Wan / MiniMax），分辨率/时长档位联动 | 批量视频；失败任务一键"重试失败" |
| 7 | **拼接导出** | 勾选镜头（悬停预览） | FFmpeg 合成完整剧集成片，点"标记完成"点亮左侧进度栏 |

### AI 参与度 vs 用户手填
- **用户手填**：只填**剧名、比例、风格** + **粘贴原著文本** + **粘贴 API Key**，其余全部由 4 个 Agent 生成。
- **AI 生成**：拍摄剧本（分集 + 场景 + 角色标注）、角色 / 场景 / 道具清单、角色定妆图、场景背景图、分镜切分、每镜视频提示词、成片。
- **AI 提议 → 用户确认**：**批量生成前的确认弹窗**（"镜头数 / 总时长 / 模型 / 分辨率"）是核心确认闸门；"AI 改写"支持换模型 / 调语气重跑；分镜提示词右侧面板可**逐个微调**。

### Wizard / step-by-step 设计
- **左侧阶段进度栏是产品灵魂**：`新建 → 剧本 → 资产 → 分镜 → 视频 → 拼接 → 完成`，每步一个大环节状态灯（灰 / 进行中 / ✓）。
- 每步都有明确"下一步 CTA"：`保存并进入制作`、`拆分分镜`、`批量生成视频`、`开始拼接`、`标记完成`。
- **阻塞 + 允许回跳**：需要按顺序做（没剧本就没法提取资产），但可以随时点左侧回上一步改；剧集列表随时展示各集制作状态。
- **未配置时全站顶部横幅提示** + 引导到设置页——是「零配置卡点」的经典处理。

### 智能填充 & 建议模式
- **画面风格 = 全局提示词注入器**：项目层选定的 `visualStyle` 会自动加进所有生图/生视频 prompt，用户不需要在每个 asset 里重复填。
- **@提及自动参考图**：分镜提示词写 `@角色名` 时**自动映射到已生成的角色参考图**——这是"字段级引用型 pre-fill"的图形化实现。
- **模型切换 → 参数联动**：顶栏换视频模型时，分辨率 / 时长档位自动切换为该厂商支持的档位（Seedance 480p/720p、MiniMax 768P/2K、Wan 480P/720P/1080P），用户不用背档位。
- **火宝快捷配置**：一个 Key 一键写 3 条厂商配置——是"配置字段自动填"的极致版本。

### 状态机与数据流
- **状态机**：项目 → 剧集 → 场景 → 分镜 → 视频任务；每层有 `draft / generating / done / failed` 状态；失败任务可"一键重试"。
- **数据流**：全 SQLite 单库 + 引用外键；剧本改写、提取资产、分镜拆分都是 Agent 写库操作，前端 auto refresh；`data/static/` 存所有媒体产物 + 缩略图 / poster 抽帧优化列表加载。
- **审核失败自动引导切模型**：真人 / 敏感内容审核失败时提示切换模型重试——这是把「重试」变成「换 adapter 重试」的产品化。

### 对 printfilm-next 的可借鉴点
1. **左侧阶段进度栏是必装项**：把 printfilm-next 的 `/`、`/story`、`/storyboards`、`/prompt`、`/export` 合并到一个 shell layout，左侧固定一栏「新建 → 故事设定 → 分集大纲 → 分场 → 关键帧 → 拼接 → 完成」，每步用状态灯 + 明确「下一步 CTA」——直接解决"每个页面独立、切来切去"的痛点。
2. **顶部横幅 + 全站引导**：未配置模型 / 未填故事圣经必填字段时，顶部横幅一句话 + CTA 跳到对应设置。
3. **粘贴原著 → 一键改写 → 保存进入下一步** 的 pattern 可以搬到 story workspace：面板 A 顶部一个大按钮"从原著 / idea 生成故事设定"，粘贴 → AI 生成 → 用户在面板里微调 → "保存并进入分集大纲"。
4. **`@角色名` 自动引用参考图**：storyboard 的场景描述里写 `@主角` 自动 hover 出参考图卡片、生成时自动注入 → 减少"要不要 copy 主角外貌描述"的心智。
5. **批量前确认弹窗**：生成分集 / 场次 / 关键帧前都弹一个"本次将生成 X 条 / 消耗预估 Y token / 使用模型 Z"的确认框——既保护用户不误触发，又强化"AI 在替我做事"的感受。
6. **失败任务一键重试 + 换模型建议**：把 error state 变成主动引导。

## 项目 3：UllrAI/CineGen-ShortDrama

### 定位与产品形态
- **工业级 AI 漫剧 / 动态漫画 / 影视分镜工作台**（React 19 + Tailwind + IndexedDB 本地库 + Gemini 2.5 Flash + Veo 3.1），核心命题：**用「关键帧驱动 + 资产约束」替代「Text-to-Video 抽卡」**。
- 4 阶段线性 Phase 结构：`Phase 01 剧本与分镜 → Phase 02 资产与选角 → Phase 03 导演工作台 → Phase 04 成片与导出`。

### 用户完整旅程（Zero → 第一段漫剧视频）

| 步 | Phase | 输入 | 输出 |
|---|---|---|---|
| 1 | 配置 | Gemini API Key（需开通 GCP 结算用 Veo） | 应用可用 |
| 2 | **Phase 01 智能剧本拆解** | 小说 / 故事大纲 + **目标时长**（30s 预告 / 3min 短剧） | 标准剧本（场次 / 时间 / 气氛） + Midjourney/SD 提示词；AI 自动规划镜头密度 |
| 3 | **Phase 02 角色定妆** | 剧本里的角色 | 每个角色的**标准参考图（Base Look）** + **衣橱系统**（多套造型：日常 / 战斗 / 受伤，保持面部特征） |
| 4 | **Phase 02 场景概念** | 剧本里的场景 | 场景概念图，保证同场景不同镜头光影一致 |
| 5 | **Phase 03 网格分镜表** | 自动继承前两步资产 | 每镜卡片：Start Frame（必） / End Frame（可选） / 上下文自动读入（场景图 + 角色当前服装图） |
| 6 | **Phase 03 关键帧生成** | 每镜 click | Start Frame（强一致性）、可选 End Frame |
| 7 | **Phase 03 视频生成** | Start + End | Veo Image-to-Video 或 Keyframe Interpolation，两帧之间平滑过渡 |
| 8 | **Phase 04 成片与导出** | 所有镜头视频 | 时间轴预览 + MP4 片段 + 高清关键帧导出（供 Premiere/AE 后期） |

### AI 参与度 vs 用户手填
- **用户手填**：故事大纲（自由文本，可长可短）、目标时长（下拉）、每个角色 / 场景 / 镜头的**微调 prompt**。
- **AI 生成**：剧本拆解 + 镜头密度规划 + Midjourney/SD 提示词自动翻译 + 角色参考图 + 场景概念图 + 每镜 Start/End Frame + 视频插值。
- **AI 提议 → 用户确认**：每张 Start Frame 是**"生成 → 用户看图 → 满意才进入视频生成"**的显式两阶段；衣橱系统里每套造型是"备选卡片"。

### Wizard / step-by-step 设计
- **Phase 编号是最强 CTA**：Phase 01 → 02 → 03 → 04，每个 Phase 都是一整块页面，快速开始文档里就是"进入 Phase 02 生成主角定妆照"这样的表述。
- **网格化分镜表**：Phase 03 的核心视觉——所有 shot 排成表格 / 卡片流，每个 shot 是一个独立单元，可跳、可批量。
- **强线性但每 Phase 内自由跳**：Phase 之间阻塞（没资产不能进 Phase 03），Phase 内可跳（先做 shot 5，再回 shot 2）。

### 智能填充 & 建议模式
- **上下文感知是本项目最强 pattern**：Phase 03 生成某一镜时，AI **自动读取「当前场景图 + 当前角色特定服装图」**注入 prompt，用户不用手动挂参考。
- **衣橱系统 = 造型状态机**：一个角色 base look 下有多套 wardrobe，每一镜自动选**当前时刻应该穿的那套**。
- **关键帧插值 = 双向约束**：Start 定"这一镜从哪开始"，End 定"到哪结束"，Veo 只负责中间过渡——把"抽卡不可控"变成"两点确定一线"。
- **文字 → 视觉自动翻译**：文字描述自动转成 Midjourney/SD 提示词，用户不用学 prompt 语法。

### 状态机与数据流
- **状态机**：Shot 卡片本身就是状态机——`empty → start frame draft → start frame confirmed → end frame confirmed → video rendered`；渲染中有实时 API 进度追踪。
- **数据流**：IndexedDB 本地库，全部数据流转在浏览器内；资产层（角色 / 场景）→ 分镜层（每 shot 的 context）→ 视频层，**下层自动引用上层**，无手动 copy。
- **数据隐私**：无后端依赖，"改哪份数据就是改哪一层"（跟 zenstory 的 Markdown as truth 是同一哲学，只是换成 IndexedDB）。

### 对 printfilm-next 的可借鉴点
1. **上下文感知式 pre-fill 是 P0 借鉴**：storyboard studio 的每一场次编辑面板，右侧默认展示"当前场次涉及的角色卡（含服装状态） + 场景卡"，AI 生成 prompt 时**自动挂参考**，用户不填 → 直接解决"面板里字段很多不知道填什么"。
2. **衣橱系统 → printfilm-next 的「角色多状态卡」**：每个角色不止一张参考图，而是"日常 / 关键剧情 / 结局"多状态，分场时自动选对应状态；对 motion_comic / animation 尤其重要。
3. **关键帧驱动 = printfilm-next 的分镜产物形态**：把 storyboard 从"文字描述"升级为"Start Frame + End Frame + 中间视频"，尤其适配 motion_comic 和 short_drama。
4. **Phase 编号 + 网格分镜表**：把 `/storyboards` 页面改成大网格 shot 卡片流，每张卡有状态灯 + 参考图缩略图 + 一键生成按钮。
5. **目标时长驱动镜头密度**：故事设定阶段就问"目标时长（30s / 3min / 每集时长）"，后续分集数 / 每集场次数 / 每场镜头数自动推导——比让用户填「集数」更贴近内容形态。
6. **文字 → Midjourney/SD prompt 自动翻译**：Prompt Center 应该有"人话 → 专业 prompt"的一键翻译按钮。

## 项目 4：zenstory-ai/drama-skills

### 定位与产品形态
- **AI 短剧 / 漫剧 11 个 Skill 合集**（面向 Claude Code / Codex / 其他支持 Agent Skill 规范的编程 Agent），来自作者自己的漫剧工作室 2025 年至今上千个项目蒸馏出的产线。
- 核心哲学：**「五份 Markdown 就是创作事实」**——每集只维护 `剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`；改哪份文件就是改哪一层决定，无并行数据库。
- **刻意把「确认」放在「生产」之前**：任何图 / 视频 / 音生成任务，先在文件里看到本次准确数量、参数、参考、adapter，用户明确确认后才调外部接口花钱。

### 用户完整旅程（Zero → 第一集成片视频）

11 个 Skill 组成的技能链：

```
$short-drama-novel-analyze  ─┐（有原著时可选，先快评再决定拆不拆）
$short-drama-develop         │─→ $short-drama-write（分集剧本）
                             │     ↓
                             │  $short-drama-assets（人物/场景/道具/声音方向 + 连续性锁）
                             │     ↓
                             │  ├→ $short-drama-image-prompts（参考图提示词）
                             │     ↓
                             │  $short-drama-storyboard（分镜 + 冻结关键帧）
                             │     ↓
                             │  $short-drama-video-prompts（视频提示词，多方言支持 MiniMax H3 等）
                             │     ↓
                             │  $short-drama-produce（**明确确认** → adapter 生产图/视频/TTS/音乐）
                             │     ↓
                             │  $short-drama-edit（剪辑：入出点 + 字幕 + 响度 + 剪辑单.md）
                             │     ↓
                             │  $short-drama-review（结构 / 内容审查）
```

典型一集从 idea 到成片的 6 步命令：`$short-drama init → -write EP01 → -assets → -image-prompts → -storyboard → -video-prompts → -produce → -edit → -review`。

### AI 参与度 vs 用户手填
- **用户手填**：project init 的题材 / 画幅、可选粘贴原著文本、每步 AI 给出产物后的**微调**、**明确确认生产**。
- **AI 生成**：故事引擎、分集地图、单集剧本、资产表 + 连续性锁短语、图片提示词、分镜、关键帧提示词、视频提示词、剪辑单。
- **AI 提议 → 用户确认**：**`$short-drama-produce` 是 4 个项目里唯一显式的"确认闸门 Skill"**——展示本次 N 个任务的内容 / 参考 / adapter / 参数，用户看到预览后打出「确认」两个字才执行。这是把「AI 主动做事」和「用户信任控制」分离得最干净的实现。

### Wizard / step-by-step 设计
- **11 个 Skill = 11 段 CTA**，README 用 Mermaid 画了完整流程图。
- **没有 GUI Wizard**，但有 `$short-drama dashboard` 本地网页面板显示项目概览、分集进度、已有媒体、剧本正文。
- **文件是唯一真实源**：`creator_markdown_check.py` 校验脚本会在跨文档引用不一致时报错（例如"SHOT-002 视觉依据没写周薄森，但关键帧 prompt 里有他"→ 明确报出原因，不只是"校验失败"）。

### 智能填充 & 建议模式
- **连续性锁（LOCK）字符串是本项目最独特的 pattern**：`视觉设定.md` 里对每个跨镜要保持的造型定义一个可原样贴进提示词的短语（如 `olive-green stand-collar service dress`），然后 `图片提示词.md` / `分镜.md` / `视频提示词.md` **原样引用**这个字符串——**字段级引用 pre-fill 的极致**。
- **`IMG-* / PLAN-* / REF-*` 三种参考图标记**：区分"项目里已存在的图（REF）"、"打算挂但还没生成的图（PLAN）"、"图片提示词槽位（IMG）"——让"AI 还差一张什么图才能生产"这件事**可追溯**。
- **视频模型方言化**：`video-prompts` skill 内置 MiniMax H3、Seedance 等不同模型的 prompt 方言（如 H3 的 6 段结构），选定模型后自动切换。
- **对白估时**：分镜阶段就按"H3 中文小样本约 4.1 字/秒"估算镜长，放不下就自动提示延长镜头或拆镜——比事后发现赶词好。
- **审查脚本给"原因"不给"错误码"**：把校验器变成"能被用户读懂的失败原因"。

### 状态机与数据流
- **状态机 = 5 份文档**：每集从 idea 到成片，就是 `剧本.md → 视觉设定.md → 分镜.md + 图片提示词.md → 视频提示词.md → 剪辑单.md` 逐份写下来。
- **数据流**：所有 skill 都读上一份文档 + 写下一份文档；`creator_markdown_check.py` 保证文档间引用一致；生产 skill 记录 provider job ID 到磁盘，中断后 `audit` + `collect --job-id` 可续跑，不重复计费。
- **确认与生产解耦**：生产 skill 从「预览 → 明确确认 → 执行 adapter → 落盘结果 → 用户查看」是一条独立管道，凭据不进项目。

### 对 printfilm-next 的可借鉴点
1. **「连续性锁」搬到 printfilm-next**：故事圣经 / 系列设定里的每个跨集要保持的元素（主角外貌 / 世界观关键词 / 视觉风格锁面）**存成一条短字符串 + 一个引用 ID**，storyboard 和 prompt center 编译时**原样注入**——直接解决"故事圣经填得再详细，生成时也不会一致"的痛点。
2. **`$short-drama-produce` 的确认闸门**：printfilm-next 的 Production Hub 应该有一个"生成前预览"面板，列本次要生成的项目数、参数、参考图、adapter、预估成本，用户明确确认才启动 job orchestrator。
3. **五份 Markdown / 数据库五张表 = 数据模型**：把 story workspace 的字段收敛成"故事圣经 / 视觉设定 / 分镜 / 图片提示词 / 视频提示词"5 张表 + 严格引用关系（当前 printfilm-next 已经接近，但可以明确"每张表都可以独立预览、独立微调、独立重生成"）。
4. **`IMG- / PLAN- / REF-` 三种参考图标记**：printfilm-next 的 asset ledger 应该区分「已生成」/「已引用但未生成」/「计划挂但外部提供」三种状态，让"下一步该生成什么"清晰化。
5. **视频模型方言化**：不同 provider 的 prompt 结构不一样（MiniMax H3 六段 / Seedance / Wan），Prompt Compiler 应该按 provider 走不同模板。
6. **校验器给"原因"**：feature completeness 检查器应该给"你在 EP03 场次 2 提到了 XX 角色，但故事圣经里没写他的外貌"这种可读的原因，不只是 "validation failed"。
7. **dashboard 页面思路**：即使核心是页面式产品，也可以在首页放一个"总览：X 集已写剧本 / Y 集已生成分镜 / Z 集已导出"，让用户知道"我现在应该去哪一集哪一步"。

## 跨项目 pattern 归纳

### 1. 流式化模式：4 个项目的「从零到成品」路径对比

| 阶段 | short-drama | huobao-drama | CineGen | drama-skills |
|---|---|---|---|---|
| 选题 / 项目初始化 | `/start` 表单 | 新建项目（剧名+比例+风格） | 配 Key + 输入 idea | `$short-drama init` |
| 故事骨架 | `/plan` | AI 改写小说 | Phase 01 智能剧本拆解 | `-develop` + `-write` |
| 角色 / 资产 | `/characters` | 提取 + 生成形象 | Phase 02 定妆 + 衣橱 + 场景 | `-assets` + `-image-prompts` |
| 分集 / 分镜 | `/outline` + `/episode` | 拆分分镜 | Phase 03 网格分镜表 | `-storyboard` |
| 视频提示词 / 生成 | —（本项目只做文本） | 批量生成视频 | Phase 03 关键帧 + Veo | `-video-prompts` + `-produce` |
| 成片 / 导出 | `/export`（文本） | 拼接导出 MP4 | Phase 04 导出 | `-edit` |
| 审查 | `/review` + `/compliance` | 审核失败换模型 | —（依赖 Veo） | `-review` |

- **共性**：都是**线性 6-8 步**，都在「资产」和「分镜」之间有明确切分。
- **差异**：CLI 系（1、4）从头到尾都是命令 + 文件，图形系（2、3）用左侧进度栏 + Phase 页面。
- **printfilm-next 应该走图形 + 进度栏路线**，但内部数据结构学 CLI 系的「每步一份可独立读写的产物文件 / 表」。

### 2. AI 主动填充热点

**必须用户自己给核心 seed 的字段**（4 个项目都要求）：
- 题材 / 内容类型（下拉，非自由文本）
- 画幅 / 比例
- 目标时长或集数
- 原始 idea 或原著文本（自由文本，但一次性给完）
- API Key / provider 凭据

**AI 最爱自动生成的字段**（覆盖 3 个及以上项目）：
- 故事结构（三幕 / 节奏曲线 / 付费卡点 / 钩子分布）
- 角色档案（外貌 / 性格 / 关系图 / 反派体系）
- 场景 / 道具清单（从剧本抽取）
- 每集分镜切分 + 每镜 prompt
- 图片 / 视频 prompt（用户不用学 MJ/SD 语法）
- 分镜时长估算（按对白字数）
- 审查 / 评分

**AI 目前还不做的**：
- 具体台词的最终定稿（用户仍会介入改）
- 参考图的最终选择（用户在多个候选里挑）
- 生产触发（都要用户明确确认）

### 3. 交互原语汇总（可复用交互元件）

| 交互原语 | 出现项目 | 描述 |

| **网格化分镜表** | 3 | 每镜一张卡，状态灯 + 缩略图 + 一键生成 |
| **Start Frame + End Frame 双帧** | 3 | 关键帧驱动视频 |
| **@角色名自动引用参考图** | 2 | prompt 里 @ 提到就自动挂图 |
| **连续性锁字符串引用** | 4 | 定义一次，多处原样注入 |

| **AI 一次性产出完整产物 → 用户 Markdown 里改** | 1, 4 | 而不是"AI 3 选 1" |
| **`.state.json` 单文件记录当前 step** | 1 | 简单直接 |
| **dashboard 总览页** | 4 | 项目 / 分集 / 媒体 / 进度一屏 |

### P0-2：把「一堆字段的表单」换成「AI 主动 pre-fill + 用户微调 + 一键改进」的双列面板

- **目标**：解决"故事圣经 / 世界设定 / 系列设定字段很多要用户自己填"的痛点。
- **参考自**：short-drama（题材 → 自动带出钩子占比 / 反派体系 / 节奏曲线）+ CineGen（上下文自动感知）+ zenstory（AI 一次性给完整草案）。
- **落地位置**：
  1. `docs/product/story-workspace-spec-v1.md` 面板 A 改造：顶部一个「从 idea / 原著生成故事设定」大按钮 + 输入框（idea 或粘贴长文），生成后**所有下方字段一次性 pre-fill 草案**，每个字段旁边加「🔄 重生成」「✨ 一键改进」「🎲 换风格」小按钮。
  2. `projectType × contentType × visualStyle` 每种组合预置一份「参考值 JSON」（钩子占比 / 节奏曲线 / 反派模式 / 场次密度 / 时长参考），设定完项目属性后**面板 B 分集大纲字段自动带默认值**。
- **优先级**：**P0**

### P0-3：分集大纲卡片流 —— 每集一张卡，一键"进入生成单集内容"

- **目标**：解决"分集大纲只有标题/摘要，用户想生成单集内容不知道怎么进入"的痛点。
- **参考自**：huobao-drama（剧集列表随时展示各集制作状态 + "进入制作"按钮）+ CineGen（网格分镜表卡片流）。
- **落地位置**：`story-workspace-spec-v1.md` 面板 B 或独立 `/episodes` 页面。每张卡显示：
  - 集号 + 标题 + 一句话梗概
  - 状态灯：`○ 未写 → ● 剧本已生成 → ● 场次已拆 → ● 关键帧已出 → ● 视频已生成 → ✓ 已导出`
  - 主 CTA：根据当前状态动态切换（"生成剧本" / "拆场次" / "去分镜" / "去生成视频"）
  - 副菜单：`重生成 / 修改 / 删除`
- **优先级**：**P0**

### P1-4：确认闸门 + 生成预览面板

- **目标**：让用户信任"AI 正在替我做事"，不误触发昂贵调用。
- **参考自**：zenstory-ai `$short-drama-produce`（预览 → 明确确认）+ huobao（批量前弹窗）。
- **落地位置**：`docs/product/production-hub-spec-v1.md` + `job-orchestrator-contract-v1.md`。所有 AI 生成（分集剧本 / 场次 / 关键帧 / 视频）触发前，弹出统一的"生成预览"面板：
  - 本次将生成 X 条（列表 + 每条的参数 / 参考 / adapter）
  - 使用模型：Z（可切换，切换后参数联动）
  - 预估耗时 / 预估成本
  - 参考资产：`[REF-角色 A 参考图 ✓] [PLAN-场景 3 概念图 待生成] [IMG-道具剑 提示词]`
  - 按钮：`确认生成` / `取消` / `选择性重跑`
- **优先级**：**P1**

### P1-5：连续性锁（LOCK）+ 参考引用系统

- **目标**：让"故事圣经写得再详细，AI 生成时也保持一致"成为可能。
- **参考自**：zenstory 连续性锁字符串 + huobao `@角色名` + CineGen 衣橱系统。
- **落地位置**：
  1. `docs/product/asset-ledger-spec-v1.md`：给每个角色 / 场景 / 视觉风格加一个 `lockPhrase: string`（如 `olive-green stand-collar service dress`），一个 `states: [{name, referenceImageId, lockPhrase}]` 数组（衣橱）。
  2. `docs/product/prompt-compiler-contract-v1.md`：编译 storyboard / video prompt 时，凡涉及该角色 / 场景，**自动把 lockPhrase 注入模板**；输入框支持 `@角色名` 快捷键自动挂参考图。
  3. `docs/product/reference-adoption-policy-v1.md`：引入 `REF- / PLAN- / IMG-` 三种参考图标记，asset ledger 显示每个引用当前状态。
- **优先级**：**P1**

### P1-6：Prompt Center 的模型方言化 + 一键人话→prompt

- **目标**：让不同 provider 的 prompt 结构自动切换；让用户不学 prompt 语法。
- **参考自**：zenstory（MiniMax H3 六段方言）+ CineGen（文字→MJ/SD prompt 自动翻译）+ huobao（模型切换参数联动）。
- **落地位置**：`docs/product/prompt-center-spec-v1.md` + `prompt-compiler-contract-v1.md`。
  - Prompt 模板按 `provider × contentType × visualStyle` 分组。
  - 编辑区顶部有"模型选择器"，切换后 prompt 结构自动重排、分辨率 / 时长档位联动。
  - 每个 prompt 输入框旁边一个"✨ 从人话生成"按钮，输入"主角站在窗前看外面下雪"，输出对应 provider 的完整 prompt。
- **优先级**：**P1**

### P2-7：一键改进 / 一键换风格 / 一键补齐

- **目标**：让「已有内容改造」也是一等操作。
- **参考自**：short-drama `/overseas` 一键切海外 + 所有项目的"重生成"。
- **落地位置**：所有 AI 生成内容的卡片右上角一个 `···` 菜单，包含：
  - 🔄 重新生成（保持种子）
  - ✨ 一键改进（AI 判断问题并修）
  - 🌏 一键换风格 / 换语言
  - 🩹 一键补齐缺失字段
- **优先级**：**P2**

### P2-8：Dashboard 总览页 + 审查评分徽章

- **目标**：一屏知道"我这个项目现在在哪"、"哪一集哪一步卡住了"。
- **参考自**：zenstory dashboard + short-drama `/review` 五维度评分。
- **落地位置**：`/` 首页改造为项目总览，卡片显示每集的状态灯、评分（如 42/50 ⭐⭐⭐⭐）、下一步 CTA；hover 卡片展开评分明细 + 分级问题清单（⛔ / ⚠️ / ℹ️）。
- **优先级**：**P2**
